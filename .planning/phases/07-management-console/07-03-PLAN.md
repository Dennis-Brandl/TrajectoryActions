    1. Create `apps/console/src/features/code-editor/hooks.ts`:
       - `useEnvironments()` — useQuery with queryKey ['environments'], calls api.environments(). (Reusable — code editor needs environment list for its selector. This is the same API call as environments page but from a different feature folder. This is intentional — co-locating hooks with features.)
       - `useEnvironmentDetail(oid: string | null)` — useQuery with queryKey ['environments', oid], calls api.environment(oid!), enabled: !!oid. Returns environment detail including actions list.
       - `useCodeVersions(actionOid: string | null, state: string | null)` — useQuery with queryKey ['code', actionOid, state], calls api.codeVersions(actionOid!, state!), enabled: !!actionOid && !!state
       - `useActiveCode(actionOid: string | null, state: string | null)` — useQuery with queryKey ['code', actionOid, state, 'active'], calls api.activeCode(actionOid!, state!), enabled: !!actionOid && !!state. Set staleTime: 30_000 and refetchOnWindowFocus: false to prevent overwriting unsaved editor changes.
       - `useSaveCode()` — useMutation calling api.saveCode(...), onSuccess invalidates ['code', actionOid, state]
       - `useActivateVersion()` — useMutation calling api.activateVersion(...), onSuccess invalidates ['code', actionOid, state]
       - `useDeleteVersion()` — useMutation calling api.deleteVersion(...), onSuccess invalidates ['code', actionOid, state]
       - `useTestCode()` — useMutation calling api.testCode(...)
       - `useAction(oid: string | null)` — useQuery with queryKey ['actions', oid], calls api.action(oid!), enabled: !!oid. Needed for template generation (input names, prop names).

    2. Create `apps/console/src/features/code-editor/CodeEditorPage.tsx`:
       This is the most complex page. Layout from ManagementConsoleSpec.md section 3.3.

       **URL query params for deep linking**: Read ?env=X&action=Y&state=Z from URL (using useSearchParams from react-router). This allows the Action Detail page's "Edit" links to pre-select.

       **State management** (all local useState):
       - selectedEnvOid: string | null (from query param or user selection)
       - selectedActionOid: string | null (from query param or user selection)
       - selectedState: string | null (from query param or user selection)
       - editorCode: string (current code in editor — may differ from saved)
       - viewingVersionId: string | null (null = editing active, string = viewing specific version)
       - isDirty: boolean (editorCode differs from loaded code)

       **Left panel (selectors + actions)**:
       a. Environment selector dropdown (shadcn Select):
          - Options from useEnvironments() — show environment name
          - On change: reset action and state selections
       b. Action selector dropdown:
          - Options from useEnvironmentDetail(selectedEnvOid) — show action name from environment's actions list
          - On change: reset state selection
       c. State selector dropdown:
          - Options: derive from the action's visibility type
          - Observable actions: STARTING, EXECUTING, COMPLETING
          - Opaque actions: EXECUTING
          - Alternatively, use the code_status array from the action detail if available
       d. Version history list (rendered by VersionHistory component — Task 2)
       e. Save button (opens SaveDialog — Task 2)
       f. Test button (opens/toggles TestPanel — Task 2)

       **Main area (editor)**:
       a. Monaco Editor component from @monaco-editor/react:
          ```tsx
          <Editor
            height="60vh"
            language="python"
            value={editorCode}
            onChange={(v) => { setEditorCode(v ?? ''); setIsDirty(true); }}
            theme="vs-dark"
            options={{
              minimap: { enabled: false },
              fontSize: 14,
              tabSize: 4,
              wordWrap: 'on',
              automaticLayout: true,
              readOnly: viewingVersionId !== null, // read-only when viewing old version
            }}
          />
          ```
       b. Show "Unsaved changes" indicator when isDirty is true
       c. When viewingVersionId is set, show a banner: "Viewing version {N} — [Edit this version] [Back to active]"

       **Template generation (UI-12)**:
       When no code exists for the selected action+state (activeCode query returns 404 or empty):
       - Generate a template string:
         ```python
         def execute(inputs, outputs, props, action_props):
             """
             State handler for {action_name} - {state}

             Available inputs: {comma-separated input parameter names}
             Available props: {comma-separated prop names}
             Available action_props: {comma-separated action prop names}

             Write to outputs dict to set output parameters.
             Return True to advance to next state, False to stay.
             """
             return True
         ```
       - Use useAction() data to fill in parameter/prop names
       - Set this as editorCode
       - Mark isDirty = true (since it's not yet saved)

       **Loading active code**:
       When all three selectors have values, fetch active code via useActiveCode().
       On success: setEditorCode(data.code), setIsDirty(false), setViewingVersionId(null).
       On 404 (no active code): trigger template generation.

       PITFALLS:
       - useActiveCode has staleTime: 30_000 and refetchOnWindowFocus: false to avoid overwriting the editor while user is typing
       - When switching selections, clear editorCode and reset isDirty before loading new code
       - readOnly option on Monaco must change when switching between viewing old version and editing active

       - On success: close dialog, clear description input, the onSuccess handler in the hook invalidates the query cache so version list updates
       - On error: show error message
       - Disable Save button while mutation is pending
       - Props: actionOid, state, code (current editor content), onSaved callback (to reset isDirty)

    2. Create `apps/console/src/features/code-editor/VersionHistory.tsx` (UI-08 version list, UI-11 rollback):
       - Props: actionOid, state, activeVersionId (for highlighting), onSelectVersion callback
       - Uses useCodeVersions(actionOid, state)
       - Renders a scrollable list of versions:
         - Each item: "v{version_number}" + description (truncated) + created_at (formatted)
         - Active version: highlighted with Badge "Active"
         - Click a version: calls onSelectVersion(version.id) — parent loads that version's code into editor (read-only mode)
       - Rollback button on non-active versions:
         - "Activate" button that calls useActivateVersion().mutateAsync({ actionOid, state, versionId })
         - On success: query cache invalidated, active version updates
       - Delete button on non-active versions:
         - calls useDeleteVersion() with confirmation
       - Loading/empty states
       - Scroll container with max-height to prevent overflow

    3. Create `apps/console/src/features/code-editor/TestPanel.tsx` (UI-10):
       - Props: actionOid, state, code (current editor content), inputParameters (from action detail — array of {name, default_value})
       - State: testInputs — object mapping input name to value, pre-populated from inputParameters defaults
       - Renders input fields for each parameter (label + Input component)
       - "Run Test" button: calls useTestCode().mutateAsync({ actionOid, state, code, inputs: testInputs })
       - Results display (on mutation success):
         - Success/failure Badge
         - Return value
         - Outputs (JSON formatted)
         - Stdout (if any) in a preformatted block
         - Stderr (if any) in a red-tinted preformatted block
         - Duration
         - Error message and traceback if failed
       - Loading state while test runs (spinner + "Running...")
       - Collapsible panel below the editor (toggle via button in left panel)

       - Import and render SaveDialog in the left panel (below state selector, above version history)
       - Import and render VersionHistory in the left panel
       - Import and render TestPanel below the Monaco editor (conditionally shown via showTestPanel state)
       - When a version is selected from VersionHistory:
         - If it's the active version: load active code, set viewingVersionId to null, allow editing
         - If it's an old version: fetch that version's code via api.codeVersion(), set editorCode, set viewingVersionId, set editor to readOnly
       - "Edit this version" button on old-version banner: copies current editorCode, clears viewingVersionId, makes editor writable (user can then save as new version)
