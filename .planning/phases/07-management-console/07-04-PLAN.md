    1. Create `apps/console/src/features/instances/hooks.ts`:
       - `useActiveInstances()` — useQuery with queryKey ['instances', 'active'], calls api.activeInstances(), refetchInterval: 2000 (UI-13 requirement)
       - `useHistoryInstances(params?)` — useQuery with queryKey ['instances', 'history', params], calls api.historyInstances(params). No auto-refresh (historical data).
       - `useInstance(id: string)` — useQuery with queryKey ['instances', id], calls api.instance(id), refetchInterval: 2000 for active instances (UI-14 requirement). To know if active: check if current_state is not terminal (not COMPLETED, not ABORTED). Use `refetchInterval: (query) => { const data = query.state.data; return data && ['COMPLETED','ABORTED'].includes(data.current_state) ? false : 2000 }` pattern — or simpler: always 2000, TanStack handles it.
       - `useInstanceCommand()` — useMutation calling api.instanceCommand(id, command), onSuccess invalidates ['instances'] broadly

    2. Create `apps/console/src/features/instances/InstancesPage.tsx` (UI-13):
       Layout (from ManagementConsoleSpec.md section 3.4):
       - Page title: "Action Instances" with "Auto-refresh: ON" indicator (Badge)
       - Two tabs (shadcn Tabs): "Active" and "History"
         - Active tab: uses useActiveInstances(), always auto-refreshing
         - History tab: uses useHistoryInstances() with optional filter params

       - Active instances table (shadcn Table):
         - Columns: ID (truncated, link to detail), Action name, Environment name, State (with colored indicator), Since (time since started_at), Detail button
         - State indicators: colored dot/circle before state name
           - Green: STARTING, EXECUTING, COMPLETING, RESUMING, UNHOLDING, CLEARING
           - Yellow: PAUSING, PAUSED, HOLDING, HELD
           - Red: ABORTING, STOPPING
           - Gray: COMPLETED, ABORTED, STOPPED
         - Each row is clickable — navigates to /instances/{id}
         - Empty state: "No active instances"

       - History instances table:
         - Columns: ID, Action, Environment, Final Status (Badge), Duration, Completed At
         - Filterable: environment, action, status filter inputs above the table
         - Simple client-side filtering is acceptable for history (or server-side if the hook supports query params)

    3. Create `apps/console/src/features/instances/InstanceDetailPage.tsx` (UI-14):
       - useParams() for :id
       - useInstance(id) with 2s auto-refresh
       - Loading/error states

       Layout (from ManagementConsoleSpec.md section 3.4 — Instance Detail):
       - Back link to /instances
       - Header: "Instance {id}" (truncated), action name (visibility badge), environment name
       - Workflow ID and Step ID if available

       - Section: "Current State" — large state display with colored indicator
       - Command buttons (below state):
         - Show based on current state and action visibility:
         - Observable active: Pause, Abort, Stop buttons
         - Observable paused: Resume, Abort buttons
         - Observable held: Unhold, Abort buttons
         - Terminal states: no buttons (disabled or hidden)
         - Each button calls useInstanceCommand().mutateAsync({ id, command })
         - Disable while mutation is pending
         - Show error toast/message if command fails (e.g., 409 conflict)

       - Section: "State Timeline" — vertical timeline visualization:
         - For each entry in state_history array:
           - Colored dot (same scheme as list)
           - State name
           - Entered timestamp (formatted)
           - Duration in that state (if exited — difference to next entry's timestamp)
           - "running..." if it's the current (last) state and not terminal
         - Future states shown as empty circles (for observable: show expected path)

       - Section: "Input Parameters" — key-value pairs from input_parameters
       - Section: "Output Parameters" — key-value pairs from output_parameters (may be empty/partial while running)
       - Section: "Pinned Code Versions" — table showing state -> version_number for each pinned version

    NOTES:
    - The 2-second auto-refresh means the state timeline updates in near real-time as the instance progresses
    - Command buttons should be disabled when a command mutation is in-flight to prevent double-sends
    - State color mapping should be a shared utility (used in both list and detail)
