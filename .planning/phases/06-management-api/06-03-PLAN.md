Append instance monitoring, log, and settings endpoints to the management router in `packages/server/src/routes/management.ts`, after the code management section.

**IMPORTANT: CONTEXT.md locked decision requires separate active/history endpoints — NOT a unified list with status filter.** The CONTEXT.md states: "Separate active instances endpoint (currently running) and history endpoint (terminal instances) — not a unified list". This must be honored.

**MGMT-13a: GET /instances/active** (currently running instances)

- Register this route BEFORE `/instances/:id` to avoid Express treating "active" as an `:id` param.
- Query instances where `completed_at IS NULL`. Use `instanceRepo.findActive()` if available, or build a dynamic query at the route level using `db.prepare()`:
  ```typescript
  const rows = db
    .prepare('SELECT * FROM instances WHERE completed_at IS NULL ORDER BY created_at DESC')
    .all()
  ```
- Accept query params for filtering: `?environment_oid=`, `?action_oid=`
- No pagination needed for active instances (bounded by pool size, typically small set)
- Enrich each instance with `action_name` and `environment_name`:
  ```typescript
  const action = actionRepo.findByOid(instance.action_oid)
  const env = environmentRepo.findByOid(instance.environment_oid)
  return {
    ...instance,
    action_name: action?.local_id ?? 'Unknown',
    environment_name: env?.local_id ?? 'Unknown',
  }
  ```
- Response: `{ data: enrichedInstances, meta: { total: enrichedInstances.length } }`

**MGMT-13b: GET /instances/history** (terminal instances)

- Register this route BEFORE `/instances/:id` to avoid Express treating "history" as an `:id` param.
- Query instances where `completed_at IS NOT NULL`.
- Accept query params: `?environment_oid=`, `?action_oid=`, `?page=`, `?page_size=`, `?sort=`, `?order=asc|desc`
- Pagination: offset-based using page/page_size. Default page=1, page_size=50, max 200.
  ```typescript
  const page = Math.max(1, Number(req.query.page) || 1)
  const pageSize = Math.min(200, Math.max(1, Number(req.query.page_size) || 50))
  ```
- Build dynamic queries at the route level using `db.prepare()`:
  ```typescript
  let whereClauses: string[] = ['completed_at IS NOT NULL']
  let params: unknown[] = []
  if (actionOid) {
    whereClauses.push('action_oid = ?')
    params.push(actionOid)
  }
  if (environmentOid) {
    whereClauses.push('environment_oid = ?')
    params.push(environmentOid)
  }
  const where = `WHERE ${whereClauses.join(' AND ')}`
  ```
  Then count query + paginated select query. Parse JSON fields from raw rows to match Instance shape.
- Sorting: allow sort by `created_at`, `completed_at`, `state`, `action_oid` with safe allowlist. Default: `completed_at DESC`.
  ```typescript
  const SORTABLE_FIELDS = new Set(['created_at', 'completed_at', 'state', 'action_oid'])
  const sortField = SORTABLE_FIELDS.has(req.query.sort as string)
    ? (req.query.sort as string)
    : 'completed_at'
  const sortOrder = req.query.order === 'asc' ? 'ASC' : 'DESC'
  ```
- Enrich each instance with `action_name` and `environment_name` (same as active endpoint)
- Response envelope:
  ```typescript
  { data: enrichedInstances, meta: { total, page, page_size, total_pages: Math.ceil(total / pageSize) } }
  ```

**Route registration order for /instances/\* endpoints:**

```
GET  /instances/active               (literal — FIRST)
GET  /instances/history              (literal — FIRST)
GET  /instances/:id                  (parameterized — SECOND)
POST /instances/:id/command          (parameterized — SECOND)
```

**MGMT-14: GET /instances/:id** (management detail view)

- Call `instanceRepo.findById(req.params.id as string)` — 404 if not found
- Enrich with action_name and environment_name
- Return full instance including state_history, pinned_code_versions, input/output parameters
- Response: `{ data: enrichedInstance, meta: {} }`

**MGMT-15: POST /instances/:id/command** (from console)

- Validate body: `validateBody(req.body, { command: { required: true, type: 'string' }, reason: { required: false, type: 'string' } })`
- Valid commands: PAUSE, RESUME, HOLD, UNHOLD, ABORT, STOP, CLEAR
- Check command is valid before instance lookup (same pattern as protocol commands router):
  ```typescript
  const VALID_COMMANDS = new Set(['PAUSE', 'RESUME', 'HOLD', 'UNHOLD', 'ABORT', 'STOP', 'CLEAR'])
  if (!VALID_COMMANDS.has(command)) {
    return void res.status(422).json({
      error: {
        code: 'INVALID_COMMAND',
        message: `Unknown command: ${command}`,
        details: { command },
      },
    })
  }
  ```
- Check instance exists via `manager.getInstance(id)` — 404 if not
- Call `await manager.sendCommand(id, command)` — let errors propagate to errorHandler (InvalidStateTransitionError -> 409)
- Return: `{ data: { instance_id: id, command, accepted: true }, meta: {} }`

**MGMT-16: GET /log** (query log entries)

- Accept query params: `?action_name=`, `?environment_oid=`, `?status=` (maps to finalStatus), `?from=` (maps to startDate), `?to=` (maps to endDate), `?page=`, `?page_size=`, `?sort=`, `?order=`
- Build LogQueryFilters object from query params:
  ```typescript
  const filters: LogQueryFilters = {}
  if (req.query.action_name) filters.actionName = req.query.action_name as string
  if (req.query.environment_oid) filters.environmentOid = req.query.environment_oid as string
  if (req.query.status) filters.finalStatus = req.query.status as FinalStatus
  if (req.query.from) filters.startDate = req.query.from as string
  if (req.query.to) filters.endDate = req.query.to as string
  filters.limit = pageSize
  filters.offset = (page - 1) * pageSize
  ```
- Call `logRepo.query(filters)` which returns `{ entries, total }`
- Compute pagination metadata: page, page_size, total_entries: total, total_pages
- Add log_config section: `{ max_entries: settingsRepo.getNumericValue('log_max_size'), current_entries: logRepo.count(), oldest_entry_at }` — for oldest_entry_at, use a simple query or getRecent logic
- For sorting: LogRepository.query() always orders by `id DESC`. If the user requests different sort, we can either:
  a) Accept that log sorting is fixed (id DESC = newest first) and document it
  b) Build dynamic ORDER BY at route level
  Simplest: keep the default (id DESC). If `sort` or `order` are requested, note that log query has fixed ordering. This is fine for v1.
- Response: `{ data: entries, meta: { page, page_size, total_entries: total, total_pages, log_config: { max_entries, current_entries, oldest_entry_at } } }`

**MGMT-17: GET /log/:id** (single entry)

- Call `logRepo.findById(Number(req.params.id))` — 404 if not found (id is numeric)
- Response: `{ data: entry, meta: {} }`

**MGMT-18: GET /settings** (list all)

- Call `settingsRepo.getAll()`
- Response: `{ data: settings, meta: {} }`

**MGMT-18: PUT /settings/:key** (update)

- Validate body: `validateBody(req.body, { value: { required: true, type: 'string' } })`
- Get previous value: `const previousValue = settingsRepo.getValue(key)`
- Call `settingsRepo.update(key, value)` — this validates and throws NotFoundError or ValidationError (caught by errorHandler)
- Apply side effects:
  - `python_pool_size`: call `manager.resizePool(Number(value))`
  - `log_max_size`: call `logRepo.trimToSize(Number(value))`
- Response: `{ data: { key, value, previous_value: previousValue, applied: true }, meta: {} }`

Import `LogQueryFilters` from `@trajectory/storage` and `FinalStatus` from storage types if not already imported.
Import `validateBody` from `../validation.js` if not already imported at top of file.
