Implement these endpoints (each as a section with comment header matching the existing codebase style):

**MGMT-02: POST /upload** (multipart)

- Receive files via multer `upload.array('files')`
- Validate all files have .wfenvir or .wfaction extension (case-insensitive)
- Parse all JSON files; if any fail to parse, return 400 immediately
- Validate required fields in each parsed object:
  - For .WFenvir: root object is a StoredEnvironmentSpecification with `oid`, `local_id`, `version`, `last_modified_date`, `schemaVersion` (note camelCase in file, maps to schema_version), `action_property_specifications`, `value_property_specifications`, `resource_property_specifications`, `included_actions` array. Each included_action has `oid`, `local_id`, `version`, `last_modified_date`, `action_visibility`, `input_parameter_specifications`, `output_parameter_specifications`, `property_specifications`.
  - For .WFaction: standalone action with same fields as StoredActionSpecification (oid, local_id, version, last_modified_date, environment_oid, action_visibility, etc.)
- Wrap ALL DB operations in a single `createTransactionHelper(db).transaction(() => { ... })` for all-or-nothing semantics
- For each .WFenvir file inside the transaction:
  1. Before upsert, get existing actions via `actionRepo.findByEnvironment(env.oid)` for diff computation
  2. Call `environmentRepo.upsert(envInput)` (maps schemaVersion -> schema_version, sets source_filename from file.originalname)
  3. For each included_action: call `actionRepo.upsert(actionInput)` with `environment_oid` set to the environment's OID
  4. Delete orphaned actions: find actions in DB for this env OID but not in the incoming action set, call `actionRepo.delete(oid)` for each. Also `codeVersionRepo.deleteByAction(oid)` for their code.
  5. Compute diff: { added: [...local_ids], removed: [...local_ids], modified: [...local_ids] } by comparing incoming vs existing action sets
- For each .WFaction file: `actionRepo.upsert(actionInput)` (standalone action)
- Return status 200 with `{ data: { imported: [...summaries], diff: {...} }, meta: {} }` where each summary includes `{ type, oid, local_id, version, actions_count, status: 'created'|'updated' }`
- On validation error, return 400 with `{ error: { code: 'VALIDATION_ERROR', message, details: { filename } } }`

**MGMT-03: GET /environments**

- Call `environmentRepo.findAll()`
- For each environment, enrich with `action_count: actionRepo.countByEnvironment(env.oid)`
- Response envelope: `{ data: enrichedEnvs, meta: { total: enrichedEnvs.length } }`

**MGMT-04: GET /environments/:oid**

- Call `environmentRepo.findByOid(req.params.oid as string)`
- If not found, return 404 with `{ error: { code: 'NOT_FOUND', message: 'Environment not found', details: {} } }`
- Enrich with actions list: `actionRepo.findByEnvironment(oid)` mapped to summary objects (oid, local_id, version, action_visibility, input param count, output param count, states_with_code via codeVersionRepo)
- Return `{ data: enrichedEnv, meta: {} }`

**MGMT-05: DELETE /environments/:oid**

- Check environment exists (404 if not)
- Check for active instances: `actions = actionRepo.findByEnvironment(oid)`, then for each action check `instanceRepo.findByAction(action.oid).some(i => i.completed_at === null)`. If any active, return 409 `{ error: { code: 'CONFLICT', message: 'Cannot delete environment with active instances', details: {} } }`
- Delete in transaction with **explicit ordering** to avoid referencing deleted data:
  1. Fetch the action list BEFORE any deletions: `const actions = actionRepo.findByEnvironment(oid)`
  2. For each action, delete its code versions first: `code_versions_removed += codeVersionRepo.deleteByAction(action.oid)` (count returned)
  3. Delete all actions for the environment: `const actions_removed = actionRepo.deleteByEnvironment(oid)` (returns count)
  4. Delete the environment itself: `environmentRepo.delete(oid)`
- Return `{ data: { deleted: true, environment_oid: oid, actions_removed, code_versions_removed }, meta: {} }`

**MGMT-06: GET /actions/:oid**

- Call `actionRepo.findByOid(req.params.oid as string)`
- If not found, return 404
- Enrich with:
  - `environment_name`: `environmentRepo.findByOid(action.environment_oid)?.local_id ?? 'Unknown'`
  - `code_summary`: compute from `codeVersionRepo.findByAction(action.oid)` — states_with_code (unique states), total_versions count, last_code_update (max created_at)
- Return `{ data: enrichedAction, meta: {} }`

**MGMT-01: GET /dashboard**

- Container info: uptime_seconds (`Math.floor(process.uptime())`), started_at (derived), node_version (`process.version`), python_version (cached), db_path (from constructor param or 'in-memory'), db_size_bytes (try `statSync(dbPath).size`, catch null), memory_rss_bytes (`process.memoryUsage().rss`)
- Pool status: `manager.poolStatus` (size, idle, busy, queued)
- Environments: `{ total_count: environmentRepo.count(), total_actions: actionRepo.count() }`
- Instances: `{ active_count: instanceRepo.countActive() }`, plus `completed_today` and `aborted_today` via `logRepo.query()` with startDate set to today midnight UTC and appropriate finalStatus filter
- Log: `{ total_entries: logRepo.count(), max_entries: settingsRepo.getNumericValue('log_max_size'), oldest_entry_at }` — oldest_entry_at via `logRepo.query({ limit: 1 })` ordered ASC (or use getRecent with reversed logic; simplest: query with limit 1 offset 0 returns newest, so use a raw query or just check the first entry from a full count)
- Recent log entries: accept optional `?count` query param (default 10), use `logRepo.getRecent(count)` mapped to summary objects (id, action_name, environment_name, final_status, duration_ms, completed_at)
- Accept optional `?timeframe` query param for recent entries filtering
- Use `{ data, meta }` envelope pattern for consistency
- For DB path: the factory should accept `dbPath: string` as a parameter (passed from index.ts)
