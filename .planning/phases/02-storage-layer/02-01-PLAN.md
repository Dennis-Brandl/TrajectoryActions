1. Create `packages/storage/src/migrations/runner.ts`:
   - Export a `Migration` interface: `{ name: string; up: (db: BetterSqlite3.Database) => void }`
   - Export a `runMigrations(db: BetterSqlite3.Database, migrations: Migration[]): void` function that:
     a. Creates `_migrations` table if not exists: `CREATE TABLE IF NOT EXISTS _migrations (id INTEGER PRIMARY KEY, name TEXT NOT NULL UNIQUE, applied_at TEXT NOT NULL)`
     b. Reads already-applied migration names from `_migrations`
     c. Sorts migrations by name (string comparison — `001-` prefix ensures order)
     d. For each unapplied migration: calls `migration.up(db)` and inserts into `_migrations`
     e. Wraps the entire apply loop in `db.transaction()` — if any migration fails, all rollback
   - The function receives `db` as parameter (not imported from database.ts) for testability

2. Create `packages/storage/src/migrations/001-initial-schema.ts`:
   - Export `const migration: Migration` with name `'001-initial-schema'`
   - The `up` function uses `db.exec()` to create ALL 6 tables with exact SQL from StorageSpec.md:
     - environments table (with all columns and constraints)
     - actions table (with FK to environments ON DELETE CASCADE, idx_actions_environment index)
     - code_versions table (with FK to actions ON DELETE CASCADE, UNIQUE constraint on action_oid+state+version_number, idx_code_versions_action_state index, idx_code_versions_active partial index WHERE is_active = 1)
     - instances table (with FKs to actions and environments — NO CASCADE, 4 indexes: idx_instances_state, idx_instances_action, idx_instances_workflow, idx_instances_cleanup partial index)
     - execution_log table (with AUTOINCREMENT, CHECK on final_status, 5 indexes: idx_log_action, idx_log_environment, idx_log_status, idx_log_completed, idx_log_oldest)
     - settings table (with CHECK on value_type)
   - After tables: seed 4 default settings using prepared statements (not db.exec with values):
     - log_max_size: '10000', number
     - python_pool_size: '4', number
     - execution_timeout_ms: '60000', number
     - instance_retention_hours: '24', number
   - Use `db.exec()` for DDL (CREATE TABLE, CREATE INDEX) and `db.prepare().run()` for seed data
