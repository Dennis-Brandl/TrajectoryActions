1. Create `packages/storage/src/repositories/log.repository.ts`:
   - Constructor receives `db: BetterSqlite3.Database`
   - Pre-compile all prepared statements in constructor
   - Private `fromRow(row)`: parse JSON columns (input_parameters, output_parameters, states_executed, code_versions_used)
   - Methods (all synchronous):
     - `insert(input: ExecutionLogInput, maxSize: number): ExecutionLogEntry` — In a transaction:
       a. INSERT the log entry (id is AUTOINCREMENT, omitted from input)
       b. Get the last insert rowid to return the created entry
       c. Trim: `SELECT COUNT(*) FROM execution_log`. If count > maxSize, DELETE the oldest `(count - maxSize)` entries using `DELETE FROM execution_log WHERE id IN (SELECT id FROM execution_log ORDER BY id ASC LIMIT ?)`. Uses idx_log_oldest index.
       d. Return the created log entry
     - `findById(id: number): ExecutionLogEntry | null` — SELECT by PK
     - `query(filters: LogQueryFilters): { entries: ExecutionLogEntry[]; total: number }` — Dynamic query builder:
       Supported filters:
       - `actionOid?: string` — WHERE action_oid = ?
       - `actionName?: string` — WHERE action_name LIKE ?  (partial match with %)
       - `environmentOid?: string` — WHERE environment_oid = ?
       - `environmentName?: string` — WHERE environment_name LIKE ?
       - `finalStatus?: FinalStatus` — WHERE final_status = ?
       - `startDate?: string` — WHERE completed_at >= ? (ISO 8601)
       - `endDate?: string` — WHERE completed_at <= ? (ISO 8601)
       - `limit?: number` — LIMIT (default 50, max 500)
       - `offset?: number` — OFFSET (default 0)
       Build WHERE clause dynamically from provided filters. Run two queries: one for total COUNT(*) (without LIMIT/OFFSET), one for the actual rows (with LIMIT/OFFSET, ORDER BY id DESC).
       Return `{ entries, total }` for pagination.
       NOTE: Since filters are dynamic, you cannot pre-compile a single prepared statement. Build the SQL string dynamically with `?` placeholders and call `db.prepare(sql).all(...params)`. This is safe because values are parameterized.
     - `trimToSize(maxSize: number): number` — Trim log to maxSize. Return count of deleted entries. This is called when log_max_size setting is reduced (per CONTEXT.md: "excess entries trimmed immediately on setting reduction").
     - `count(): number` — SELECT COUNT(*)
     - `getRecent(limit: number): ExecutionLogEntry[]` — SELECT ORDER BY id DESC LIMIT ?
     - `deleteAll(): number` — DELETE FROM execution_log. Return count. For testing/maintenance.

Define `LogQueryFilters` interface in the same file or in types.ts.
