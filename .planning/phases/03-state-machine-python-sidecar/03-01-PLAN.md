Define supporting types:

- `CodeExecutionResult`: `{ success: boolean; outputs: Record<string, string>; return_value: boolean | null; error?: string; error_type?: string; traceback?: string; execution_time_ms: number; stdout_capture: string; stderr_capture: string }`

If @packages/storage/src/types.ts Instance type does not have this field, add it to the Instance type and the instances table schema as a nullable text column. The `enterState()` updates parameter includes `traceback?: string` for this purpose.
- `CodeExecutor`: async function type `(instanceId: string, state: string, sourceCode: string, inputs: Record<string, string>, outputs: Record<string, string>, envProps: Record<string, unknown>, actionProps: Record<string, unknown>, timeoutMs: number) => Promise<CodeExecutionResult>`
- `StateMachineCallbacks`: `{ onStateChange?: (instanceId: string, state: string, instance: Instance) => void; onTerminal?: (instanceId: string, state: string, instance: Instance) => void; onError?: (instanceId: string, error: Error) => void }`

Create `StateMachine` class:

- Constructor receives:
  - `instanceRepo: InstanceRepository` — for persisting state changes
  - `codeVersionRepo: CodeVersionRepository` — for looking up pinned code
  - `settingsRepo: SettingsRepository` — for reading execution_timeout_ms
  - `codeExecutor: CodeExecutor` — the injectable callback for running Python code (or mock in tests)
  - `callbacks?: StateMachineCallbacks` — optional event hooks

- **`async enterState(instanceId: string, newState: string, updates?: { started_at?: string; completed_at?: string; error?: string; traceback?: string }): Promise<void>`**
  The core pipeline from StateMachineSpec.md §3:
  a. Call `instanceRepo.updateState(instanceId, newState, updates)` — this appends to state_history and persists synchronously
  b. If update returns null, throw EngineError('Instance not found during state transition')
  c. Read the updated instance
  d. Call `callbacks?.onStateChange?.(instanceId, newState, updatedInstance)` — for SSE emission (Phase 5)
  e. Determine visibility from instance
  f. Look up pinned code version for this state:
  - Read `instance.pinned_code_versions` (it's an array of `{ state: string, code_version_id: string }`)
  - Find the entry matching `newState`
  - If found, call `codeVersionRepo.findById(entry.code_version_id)` to get source code
    g. If code found:
  - Read `execution_timeout_ms` from settingsRepo
  - Build inputs/outputs from instance (parse input_parameters and output_parameters as `Record<string, string>`)
  - Build envProps and actionProps (these will be empty `{}` for now — parameter resolution is Phase 4)
  - Call `await codeExecutor(instanceId, newState, codeVersion.source_code, inputs, outputs, envProps, actionProps, timeoutMs)`
  - Handle result: - If `result.success === true`: - Update instance output_parameters with `result.outputs` via `instanceRepo.updateOutputParameters()` - Mark state as code-executed via `instanceRepo.markStatesWithCodeExecuted()` - If `result.return_value === false` AND newState is `'EXECUTING'`:
    Trigger code-initiated HOLD: call `await this.enterState(instanceId, 'HOLDING')`
    Then auto-advance HOLDING -> HELD: after HOLDING enters, if no HOLDING code, it auto-advances to HELD
    Return (do NOT auto-advance to COMPLETING) - Otherwise (return_value is true or anything non-false):
    Get auto-advance target from AUTO_ADVANCE (or OPAQUE_AUTO_ADVANCE based on visibility)
    If target exists, call `await this.enterState(instanceId, target)` recursively - If `result.success === false`: - Store two-tier error detail per CONTEXT.md: full traceback stored on instance for management console, summary (error_type + message) for workflow clients: - `instanceRepo.updateState(instanceId, newState, { error: result.error, traceback: result.traceback })` - The `error` field holds the summary: `${result.error_type}: ${result.error}` - The `traceback` field holds the full Python traceback string (stored separately on the Instance record) - Transition to ABORTING: `await this.enterState(instanceId, 'ABORTING', { error: result.error })`
    h. If NO code found:
  - Get auto-advance target from AUTO_ADVANCE / OPAQUE_AUTO_ADVANCE
  - If target exists, call `await this.enterState(instanceId, target)` recursively
  - If no target (terminal state like COMPLETED or ABORTED):
    - Set completed_at if terminal
    - Call `callbacks?.onTerminal?.(instanceId, newState, instance)`

- Private state:
  - `executingInstances: Set<string>` — tracks instance IDs currently running code in processCurrentState
  - `deferredCommands: Map<string, string>` — maps instanceId to a deferred command (HOLD, STOP, ABORT) that arrived during code execution

- **`async sendCommand(instanceId: string, command: string): Promise<void>`**
  Per StateMachineSpec.md §4, with deferred-HOLD extension from CONTEXT.md:
  a. Read instance from `instanceRepo.findById(instanceId)`
  b. If not found, throw EngineError
  c. Determine visibility from instance
  d. Call `validateCommand(instance.state, command, instance.visibility)` — throws InvalidStateTransitionError if invalid
  e. The target state is the return value of validateCommand
  f. **Deferred command check (CONTEXT.md: "HOLD during code execution must be deferred until code finishes"):**
  - If command is HOLD (or STOP/ABORT) AND `executingInstances.has(instanceId)`:
    - Store the command: `deferredCommands.set(instanceId, command)`
    - Return immediately — the command will be applied when processCurrentState finishes code execution
  - Otherwise: call `await this.enterState(instanceId, targetState)` immediately

- **In `processCurrentState()`, after code execution completes (after result handling):**
  - Check `deferredCommands.has(instanceId)`
  - If a deferred command exists:
    - Delete it from the map
    - Call `await this.sendCommand(instanceId, deferredCommand)` to apply the deferred transition
    - Return (skip normal auto-advance, since the deferred command takes precedence)
  - The `executingInstances` set is updated: add instanceId before calling codeExecutor, remove in finally block

Architecture note — the class uses a two-method split:

- `enterState(instanceId, newState, updates?)`: persists the new state via updateState, then calls `processCurrentState(instanceId)`
- `processCurrentState(instanceId)` (private): reads instance, looks up code for current state, executes or auto-advances. This is the shared code-lookup-and-advance logic (steps f-h above).

- **`async startInstance(instanceId: string): Promise<void>`**
  Convenience method to kick off the state machine after instance creation.
  The instance is already created with its initial state (STARTING for observable, POSTED for opaque).
  startInstance reads the instance and calls `processCurrentState(instanceId)` to begin the pipeline from the already-set initial state — without re-entering via enterState (which would create a duplicate state_history entry).
